# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope Note

Phase 10 is a refactoring and simplification phase. It introduces **no new screens, no new routes, and no new user-facing features**. The only frontend change is decomposing three large page files into focused components (D-05). This UI-SPEC defines the contract that extracted components must conform to — all values are inherited from the established design system and must not deviate.

## Spacing Scale

Declared values (multiples of 4 only). Inherited from shadcn/Tailwind defaults — do not introduce new custom spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact form field spacing, list item gaps |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, modal content padding |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top/bottom spacing |

Exceptions: Touch targets on mobile must be minimum 44px height per ui-ux-pro-max skill `touch-target-size` rule. All extracted form components must preserve existing 44px button heights.

## Typography

All values are inherited from the existing Geist Variable setup. Extracted components must not introduce new font sizes or weights.

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Body | 14px | 400 (regular) | 1.5 | Tailwind default / existing pages |
| Label | 14px | 500 (medium) | 1.4 | Existing form label pattern |
| Heading | 20px | 600 (semibold) | 1.2 | Existing StatCards / modal headings |
| Display | 28px | 700 (bold) | 1.1 | CheckWidget verdict number only |

Constraint: Only these 4 sizes and 3 weights are permitted in extracted components. Any new form or modal component must use body (14px/400) for field text and label (14px/500) for field labels.

## Color

All values from `web/src/index.css` `:root` block. OLED dark theme only — no light mode variant exists.

| Role | Token | Computed Value | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `--background` | `oklch(0.09 0.020 255)` near-black | Page background, base surfaces |
| Secondary (30%) | `--card` / `--sidebar` | `oklch(0.13 0.022 255)` dark navy | Cards, sidebar, modals, extracted form shells |
| Accent (10%) | `--accent` | `oklch(0.72 0.19 142)` green | Reserved list below |
| Primary | `--primary` | `oklch(0.58 0.22 264)` blue | Primary action buttons only |
| Destructive | `--destructive` | `oklch(0.65 0.22 25)` red-orange | Destructive actions only |
| Muted | `--muted-foreground` | `oklch(0.58 0.034 228)` | Secondary text, placeholder copy |

Accent (`--accent`, green) reserved for:
- Confirmed/paid state indicators on peer debt rows
- Positive balance values in stat cards
- Risk level LOW badge
- `verdict-yes` card in CheckWidget

Accent must not be used for: generic hover states, form focus rings (use `--ring` / blue primary instead), navigation active items (use `--sidebar-primary`).

Custom verdict tokens (do not use outside their designated components):
- `--color-verdict-yes` / `--color-verdict-yes-tint` — CheckWidget YES state only
- `--color-verdict-no` / `--color-verdict-no-tint` — CheckWidget NO state only
- `--color-verdict-wait` / `--color-verdict-wait-tint` — CheckWidget WAIT state only
- `--color-risk-*` — Risk badge only

## Component Extraction Contract

This section defines constraints specific to D-05 (frontend decomposition). All extracted components are internal refactors — they must produce identical rendered output to the inline code they replace.

### Extraction targets

| Source file | Lines | Components to extract | Landing path |
|-------------|-------|-----------------------|--------------|
| `web/src/pages/friends.tsx` | 1,342 | `FriendForm`, `DebtForm`, `GroupEventForm`, `ParticipantEditor` | `web/src/components/` |
| `web/src/pages/accounts.tsx` | 835 | Account form component, account modal shell | `web/src/components/` |
| `web/src/pages/transactions.tsx` | 789 | Transaction form component, transaction modal shell | `web/src/components/` |

### Extracted component rules

1. **Props interface required.** Every extracted component must declare an explicit TypeScript props interface.
2. **No new state.** State that already existed in the parent page stays in the parent unless the extraction makes it clearly local. Do not introduce new `useState` calls for state that crosses component boundaries.
3. **Same shadcn primitives.** Use only already-installed components: `alert-dialog`, `badge`, `button`, `card`, `dialog`, `input`, `label`, `select`, `separator`, `sheet`, `sonner`, `switch`, `textarea`, `toggle`, `tooltip`. Do not install new shadcn components as part of this extraction.
4. **No layout changes.** Extraction must not alter rendered DOM structure, class names, or visual appearance.
5. **Lucide icons only.** No new icon sets. Use existing Lucide imports.

## Copywriting Contract

Phase 10 introduces no new user-visible copy. The contracts below document existing copy that extracted components must preserve verbatim.

| Element | Copy | Context |
|---------|------|---------|
| Primary CTA (transactions) | "Add Transaction" | TransactionForm submit |
| Primary CTA (accounts) | "Add Account" | AccountForm submit |
| Primary CTA (friends) | "Add Friend" | FriendForm submit |
| Primary CTA (peer debt) | "Add Debt" | DebtForm submit |
| Primary CTA (group event) | "Create Event" | GroupEventForm submit |
| Delete confirmation | "This action cannot be undone. Are you sure?" | AlertDialog body for all destructive deletes |
| Delete confirm button | "Delete" | AlertDialog destructive button |
| Cancel label | "Cancel" | All dialog/sheet cancel buttons |
| Empty state (no friends) | Preserve existing copy from friends.tsx | Do not change during extraction |
| Empty state (no debts) | Preserve existing copy from friends.tsx | Do not change during extraction |
| Error state | Preserve existing sonner toast messages verbatim | Do not change error strings |

Destructive actions in this phase:
- Delete peer debt — confirmed via AlertDialog (existing pattern)
- Delete group event — confirmed via AlertDialog (existing pattern)
- Delete transaction — confirmed via AlertDialog (existing pattern, bug fix in D-08 does not change copy)

No new destructive actions are added in Phase 10.

## Interaction States

Extracted components must preserve all existing interaction states:

| State | Implementation |
|-------|----------------|
| Loading (async submit) | Button `disabled` prop + spinner or loading text — match existing pattern in each page |
| Form validation error | Inline error below field using existing pattern from each page |
| Hover on interactive elements | `cursor-pointer` via Tailwind — must be preserved from source |
| Focus ring | `outline-ring/50` via global `@layer base` — do not override |
| Transitions | `transition-colors duration-200` — match existing Tailwind utility usage |
